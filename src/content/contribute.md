# 修订与贡献

《公约》由所有人共同编辑。你不需要懂开发，不需要会 Git，甚至不需要 GitHub 账号，就能让公约变得更好。

- [邮件反馈](mailto:hi@zhblog.org)
- [GitHub Discussions](https://github.com/zhblogorg/zhblog/discussions)
- [GitHub Issues](https://github.com/zhblogorg/zhblog/issues)
- [项目仓库](https://github.com/zhblogorg/zhblog)

---

## ① 邮件反馈

**适合**：没有 GitHub 账号、不想注册新服务的朋友。

把修订建议写成邮件发送至 <hi@zhblog.org>，建议包含三点内容：

1. 想修订的条款或内容；
2. 现有表述与你的建议表述；
3. 修订理由。

> 你可以像聊天一样表达，不必拘泥于格式；建议被采纳后，会按你的意愿在[修订记录](/history)中署名。
> 如果你的提议合理且被采纳，会收到此邮箱的回复。

## ② 博文讨论

**适合**：希望深入表达观点，并把讨论沉淀在自己博客上的朋友。

写博文本身就是最“独立博客”的参与方式：

1. 在你的博客上发表对公约的讨论文章；
2. 通过邮件或议题告知我们文章链接；
3. 有价值的观点将被纳入社区讨论，重要修订会标注来源。

## ③ 提交议题或讨论

**适合**：拥有 GitHub 账号、希望公开追踪讨论进展的朋友，无需任何 Git 知识。

1. 打开[讨论](https://github.com/zhblogorg/zhblog/discussions)或[议题](https://github.com/zhblogorg/zhblog/issues)页面，发起新问题。
2. 用一段话写清建议：改哪里、怎么改、为什么；
3. 提交议题，后续的讨论与处理进度都会在议题页公开。

> 建议优先使用「讨论」，它比「议题」更适合开放式的交流。

## ④ 网页直接编辑

**适合**：有 GitHub 账号、想亲手修改文字但不会 Git 的朋友，全程在浏览器中完成。

1. 打开[公约源文件编辑页](https://github.com/zhblogorg/zhblog/edit/main/src/content/guidelines.md)，GitHub 会提示登录；
2. 像编辑普通文档一样直接修改文字；
3. 在页面底部填写一句话修改说明，点击绿色按钮 **Propose changes**；
4. GitHub 会自动生成一份修改提案（Pull Request），等待维护者审核合并即可。

> 提示：在仓库中打开任意文件后按 <kbd>e</kbd> 键，也能直接进入编辑模式。

## ⑤ Git 工作流

**适合**：熟悉 Git 工作流的朋友。

1. Fork [本站仓库](https://github.com/zhblogorg/zhblog)并创建新分支；
2. 公约正文位于 `src/content/guidelines.md`，其余页面也在 `src/content/` 目录中；
3. 本地预览：`npm install && npm run dev`；
4. 提交 Pull Request，并简要说明修订意图。

> 注意：提交前务必同步最新代码，解决冲突。

## 其他贡献

除修订条文外，你还可以：

- **润色**：人类撰写并不能十全十美，需要大家帮助完善；
- **传播**：撰写、引用或推荐公约，让更多独立博主看到它；
- **建设**：为站点贡献代码、设计与排版改进。

## 修订流程

不论通过哪种方式提出，修订都会经过同样的流程，以保证公开、透明、可追溯：

1. **提案**：通过上述任一方式提出修订建议；
2. **讨论**：社区公开讨论，形成共识；
3. **修订**：共识内容合并进正文；
4. **发布**：更新部署，并在[修订记录](/history)中登记变更。

## 修订原则

- **共识优先**：涉及核心原则的修改，需要充分的社区讨论；
- **保持简洁**：条款以易读为第一要务，避免法律文书式的长句；
- **向后兼容**：修订应尽量不使已声明遵守的博主陷入“违约”；
- **尊重署名**：被采纳的修订，按提议者意愿在修订记录中署名。

## 公示规则

并非所有修订都要经过公示，是否公示取决于改动的影响范围：

错别字、标点、排版等不改变条款含义的调整，直接并入正文并在[修订记录](/history)中登记，无需公示；

条款语义发生变化、增删条款等实质性调整，会先行公示，征得大部分人同意后再并入正文。
